# プロジェクトレポート：物理演算で可視化するIT業界の深淵「絶望の中抜きパチンコ」

## 開発を通じた「不条理の再定義」とモダンフロントエンド技術の限界への挑戦

### 1. はじめに：制作の動機とプロジェクトの目的

「優れたシステムを構築するためには、単にコードを書く能力だけでなく、外部からの不条理な構造を適切に理解し、技術者としての誇りを守るための『シニカルな視点』が必要不可欠である」。

エンジニアとして日々の業務に邁進する中で、私たちが直面するのは「技術」そのものよりも、むしろそれを取り巻く「商流」や「人間関係」という非論理的な障壁であることが少なくありません。特に、日本のIT業界において長年議論の的となっている「多重下請け構造」や「中抜き」という現象は、現場のエンジニアのモチベーションを削ぎ、技術的負債を温存させる元凶とも言えます。学習の過程で提示される「クリーンなコード」や「理想的なアーキテクチャ」をなぞるだけでは、実際の業務で直面する「なぜ自分の給料は案件単価に対してこれほどまでに低いのか」という根源的な問いに対する耐性は養われません。

多くのエンジニアにとって、給与明細に並ぶ数字は、不可解な中間搾取の結果として提示された「既定の事実」に過ぎません。その計算式はブラックボックスの中にあり、私たちは時として思考停止し、その不条理を受け入れているのではないでしょうか。あるいは、その「不条理」を改善するコストを嫌い、妥協的に現状を肯定しているのではないか。

この切実な問題意識を起点として、私は自らに一つのミッションを課しました。「エンジニアが現場で直面する、構造的な搾取という名の『不可視の損失』をエンターテインメントとして昇華し、遊びながらIT業界の不条理を再認識できる、バイラル性の高いWebアプリケーションを開発する」という挑戦です。そうして誕生したのが、元請けから銀行口座までの絶望的な旅路を物理演算で再現した、「絶望の中抜きパチンコ」です。

本プロジェクトの最大の目的は、単に社会風刺ツールを公開することに留まりません。Next.js 15を用いた最新のApp Routerアーキテクチャの実装、Tailwind CSS v4による先進的なスタイリング、Matter.jsによる高度な物理シミュレーション、電力効率を考慮した描画、そしてVercel OGを駆使した動的なエッジ画像生成まで、現代のWebフロントエンド開発における「フルサイクル・エンジニアリング」を独力で完遂することにありました。この開発過程を通じて、単なる「実装屋」ではない、プロダクト全体を統括する「プロダクト・マネジメント能力」を飛躍的に向上させることが、この挑戦の本質的な動機でした。技術を武器に、いかにして「現実」という重力に抗うか。その模索の記録が本レポートです。

### 2. アプリケーションの概要と「絶望の中抜き」の概念

「絶望の中抜きパチンコ」は、IT業界の商流という名の迷宮を、パチンコというメタファーで視覚化したシミュレーション・アプリです。ユーザーが案件を受注すると、画面上部から「案件単価」という名の巨大な金の玉が放たれます。

#### 2.1. 商流の物理的な再定義
このアプリにおいて、本来のパチンコであれば「釘」に相当する部分は、「一次請け（大手SIer）」「二次請け（中堅ソフトウェアハウス）」「自社営業のピンハネ」「謎の事務費」という、各階層のステークホルダーに置き換えられています。金の玉がこれらのピン（障害物）に衝突するたびに、リアルタイムで金額が削り取られていく演出を物理演算（Matter.js）で実装しました。

これは、単なる数字の引き算ではありません。「ガツン」という衝突音（視覚的なエフェクト）と共に、自分の取り分が物理的に剥ぎ取られていく感覚をユーザーに与えることで、抽象的な「中抜き」という概念を、直感的な「痛み」として体験させることを狙っています。玉がピンに激突し、不規則に軌道を変えながら、みるみるうちに輝きを失っていく様は、エンジニアが疲弊していくプロジェクトの進捗そのものを暗示しています。

#### 2.2. アイデンティティとしての「絶望の評価」
最終的に最下部の「銀行口座（ゴール）」に到達した際の残金に基づき、アプリはユーザーに対して残酷な評価を下します。

- **C（業界の養分）**: 「君の代わりはいくらでもいるから😊」
- **B（従順なソルジャー）**: 「経験積めるから実質プラスだよね？😉」
- **A（標準的なエンジニア）**: 「今回は頑張って単価交渉しといたよ！🫡」
- **S（奇跡の生存者）**: 「フリーランスになった方がいいのでは？🤔」

これらのメッセージは、エンジニアが実務で耳にする「耳に心地よい搾取の言葉」をサンプリングしたものです。計算された結果は即座にシェア可能で、「自分が今、どの程度の『養分』として業界を支えているのか」を可視化。SNSという鏡を通じて、自己の立ち位置を客観視させ、リプレイ性を高める設計としました。この「自己の市場価値の再認」こそが、ユーザーを惹きつける中毒性の正体です。

### 3. 使用した技術スタックとその選定理由

本プロジェクトの開発にあたっては、2026年現在のフロントエンド開発において最も洗練され、かつ高いパフォーマンスを発揮できる最新の技術スタックを選択しました。

#### 3.1. Next.js 15 (App Router)
基盤には最新のNext.js 15を採用しました。今回のアプリは単一のページで完結するシンプルな構成ですが、あえてNext.jsを選んだ理由は、サーバーサイドでのOG画像生成（Metadata API / @vercel/og）との親和性が極めて高いためです。SNSでの拡散を前提としたプロダクトにおいて、ユーザーの結果を動的に反映した画像生成は不可欠な要素であり、エッジ実行による低遅延なレスポンスを実現するために最適の選択でした。

#### 3.2. Matter.js による物理シミュレーション
本アプリの「心臓部」といえるのが、Matter.jsを用いた物理演算エンジンです。CSSアニメーションや単純なJSのランダム値では表現できない、「ピンを弾き、予測不能に落下していく玉」の挙動を再現するために導入しました。Matter.jsの柔軟な衝突検知（Events.on）を利用し、ピンの種類（商流の深さ）に応じた減額ロジックをシームレスに結合しています。物理エンジンの「決定論的な演算」と、初期値の「微弱なランダム性」の組み合わせが、商流という運命の残酷さを際立たせています。

#### 3.3. Tailwind CSS v4
スタイリングにはTailwind CSSの最新バージョン（v4）をフル活用しました。v4で刷新されたアーキテクチャにより、従来よりも少ない記述量で、ネオンサインのような光彩を放つ「ダークモード・テックUI」を実現しました。特に、ガラスモーフィズムを多用したコントロールパネルや、背景のグラデーション、そしてスキャンライン（走査線）のようなサイバー感を出すためのユーティリティ適用は、CSS-in-JSに頼らない低レイテンシな描画を可能にしました。デザイン面では、あえて「カジノ」のような高揚感と、「深夜のオフィス」のような孤独感を同居させています。

### 4. フロントエンドの実装詳細：物理演算エンジンの統合

プロジェクトの技術的ハイライトは、メインのページコンポーネントにおける物理演算ライブラリとフレームワークのライフサイクル管理の統合にあります。

#### 4.1. Reactステートとエンジン・インスタンスの同期
Matter.jsは命令的なライブラリ（Imperative）であるため、宣言的なReactの世界と共存させるには工夫が必要です。useRefを使用してエンジンのインスタンスを保持し、useEffect内でレンダリングやランナーのセットアップを行うことで、React의 再レンダリングに左右されない安定した物理演算の世界を構築しました。

特に、ゲームの初期化時にランダムなピン配列を生成する内部処理は、毎回異なる「業界の構造」を作り出し、ユーザーに「運任せの商流」というリアリティをもたらしています。また、キャンバスのスケール調整（Responsive Scaling）も重要な課題でした。モバイル端末ではピンの間隔が狭まり、玉が通りにくくなるという「物理的な難易度上昇」が発生してしまいますが、これは意図的に残すことで、リソースの少ない現場の苦しさを表現する隠し味としています。

#### 4.2. 金額減衰ロジックの非対称性
金額の減算処理には、単なる引き算ではない「非対称な減衰」を組み込みました。具体的には、所持金（案件単価）が少なくなればなるほど、一回あたりの衝突による減額比率や固定控除額を動的に調整するアルゴリズムを採用しています。

このロジックにより、所持金が30万円を切った際や60万円以下の際で、それぞれ異なる搾取の「手加減」が発生するように設計しました。これにより、ある程度削り取られた後も「微かな希望」を持たせつつ、最終的には「税金等（社会保険料）」という名の20%の強制カットがとどめを刺すという、現実の残酷さを数学的に表現しました。実装面では、`Matter.Events.on(engine, 'collisionStart', ...)` 内で、衝突対象となるBodyのラベル判定を行い、瞬時にステートを更新する高速なイベントループを構築しました。

### 5. コンテンツ設計：搾取の言語化と階層構造

本アプリケーションの「教育的価値」と「エンターテインメント性」を両立させているのが、プログラム内に定義された「搾取のメタデータ」です。

#### 5.1. 階層化された敵対者たち
ピンにはそれぞれ重みが設定されており、商流の深さを象徴しています。

- **一次請け（大手SIer）**: 大きな当たり判定と高い減額。商流の入り口で最も大きく削り取る。「管理費」の名の下に、玉（お金）の勢いを殺す役割も担います。
- **二次請け（中堅）**: 標準的なピン。着実に体力を削る。最も数が多く、最も回避が困難な「壁」として配置。
- **自社営業/ピンハネ**: 小刻みに、しかし執肋に衝突を繰り返す。一発のダメージは小さいが、連打で実質的な取り分を剥ぎ取ります。
- **謎の調整金/事務費**: 見逃しやすい小さなピン。塵も積もれば山となる。「福利厚生」という名の微細な罠。

#### 5.2. 評価コメントに込められた皮肉
「経験積めるから実質プラスだよね？」という言葉は、かつて多くのエンジニアが低単価案件にアサインされる際に言われたであろう「呪詛」の裏返しです。これらをあえてSランクからCランクのコメントとして配置することで、ユーザーは「自分が言われてきたことの正体」をメタな視点から捉え直す機会を得ます。この心理的解放が、プロダクトにおけるカタルシスとなっています。あえて毒のある絵文字を添えることで、搾取する側の「悪意のなさと無理解」を際立たせる演出は、UI/UX設計における重要な要素でした。

### 6. SNS連携とバイラル設計：エンジニアの「自虐」を刺激する

本プロジェクトを個人の趣味開発で終わらせず、社会現象としてのバイラルを狙うために、戦略的なSNS設計を行いました。

#### 6.1. 共有機能による「奴隷ランク」の可視化
動的な画像生成ロジックは、ユーザーの結果を一目で「惨状」として伝えます。赤い文字で強調された「中抜き率〇〇%」や、「あなたのSES奴隷ランク：C」という刺激的なコピーは、タイムライン上でのクリック率を劇的に高めます。人は「幸せな報告」よりも「悲惨な叫び」を共有したがるという心理を突いた設計です。このOGP画像はCanvasを使わず、Satoriエンジンによってエッジサーバー上で描画されるため、デバイスに関わらず高品質な「絶望の証明書」を生成できます。

#### 6.2. 共有ボタンのメッセージ・テンプレート
共有時のプレーンなテキストも、単なるURLの添付ではなく、生成された評価コメントを冒頭に持ってくる構成にしています。これにより、投稿を見た人が「何それ？自分もやってみたい」と思わせる「リアクションの連鎖」をプロダクト内にデザインしました。「#中抜きパチンコ」「#絶望のSES」といったハッシュタグを自動付与することで、エンジニアコミュニティ内でのトレンド化を加速させました。

### 7. 直面した課題と技術的な反省点

開発プロセスは、物理演算ゆえの予測不能なバグとの戦いでもありました。

#### 7.1. 玉の「スタック（詰まり）」問題
物理演算の世界では、稀に玉が複数のピンの間に挟まって静止してしまう「詰まり」が発生しました。これは「いつまでも結果が出ない」という最悪のUXを招きます。この反省から、beforeUpdateイベント内で玉の速度が極端に低下した場合に、ランダムな微小な力（Force）を加えて再始動させる「救済措置」を実装しました。これは、業界から抜け出せないエンジニアへのわずかな慈悲を表現しているかのようです。あるいは、無理やり動かされるという「デスマーチ」のメタファーでもあります。

#### 7.2. 物理演算の「重さ」とレスポンス
Matter.jsの計算負荷とモバイル端末での描画パフォーマンスの両立は困難でした。初期実装ではピンの数が多すぎてカクつきが発生しましたが、ピン生成アルゴリズムを改良し、視覚的な密度を保ちつつ演算対象となるBodyの数を最適化することで解決しました。また、物理演算の更新頻度（Delta time）をモニターのリフレッシュレートに同期させることで、カクつきを抑え、指に吸い付くような「搾取の体験」を実現しました。

### 8. 今後の展望と追加機能のアイデア：進化する搾取

「絶望の中抜きパチンコ」はまだ完成形ではありません。

#### 8.1. GitHub API連携による「実力ベースの搾取」
今後はGitHub APIと連携し、ユーザーのコミット履歴やリポジトリのスター数から「市場価値」を算出し、それに基づいた「初期案件単価」を設定する機能を構想しています。実績が乏しいと最初から「低単価パチンコ」からスタートし、さらなる絶望を味わうという、徹底した実力至上主義（の裏の不条理）を体現させたいと考えています。

#### 8.2. 世界搾取ランキングの統計分析
Vercel KVやPostgreSQLを活用し、全ユーザーの「累計搾取額」や「平均中抜き率」をリアルタイムで統計化する機能を追加する予定です。これにより、「現代のエンジニアがいかに構造的に搾取されているか」をビッグデータとして可視化し、業界の健全化への警鐘を鳴らす（あるいは単に笑いのネタにする）「社会学的装置」としての価値を持たせたいと考えています。グラフ化された搾取の推移は、きっと多くのエンジニアに「連帯」という名の新しい絶望を与えることでしょう。
