# プロジェクトレポート：本音ダダ漏れ「煽りLGTMジェネレーター」
## 開発を通じた「拒絶の審美眼」とフルサイクル・エンジニアリングの実践

### 1. はじめに：制作の動機とプロジェクトの目的

「優れたシステムを構築するためには、単にコードを書く能力だけでなく、外部からの過剰な要求（無茶振り）を適切に制御し、プロジェクトの健全性を維持する『拒絶の審美眼』が必要不可欠である」。

学習の過程で提示される「正解の仕様」をなぞるだけでは、実際の業務で直面する曖昧な要件や、技術的負債を生み出す急ぎの開発、そして開発者のメンタルを蝕む「終わりのない修正」に対する耐性は養われません。多くのエンジニアにとって、コードレビューにおける「LGTM（Looks Good To Me）」は、時として思考停止の同義語になりがちです。本当にそのコードは良いのか。それとも、単に「拒絶」することで発生するコミュニケーションコストを嫌い、妥協的に承認しているのではないか。

この切実な問題意識を起点として、私は自らに一つのミッションを課しました。「エンジニアが現場で直面する安易な承認文化に対するシニカルな風刺を形にし、遊びながら『批評的思考』を再認識できる、バイラル性の高いWebアプリケーションを開発する」という挑戦です。そうして誕生したのが、美しいテンプレート画像に強烈な本音（煽り文句）を添えてLGTM画像を生成する、「本音ダダ漏れ！煽りLGTMジェネレーター」です。

本プロジェクトの最大の目的は、単にジョークツールを公開することに留まりません。企画立案からUI/UXデザイン、Next.js 16を用いた最新のApp Routerアーキテクチャの実装、Tailwind CSS v4による先進的なスタイリング、そして `@vercel/og` を駆使した動的なエッジ画像生成まで、現代のWebアプリケーション開発における「フルサイクル・エンジニアリング」を独力で完遂することにありました。

エンジニアの間で語り草となるような「あるある」エピソードを、画像のサブテキストという形で可視化すること。そしてその開発過程を通じて、自分自身が「保守性の高いコードを書く」だけでなく「プロジェクトの質を担保するためのコミュニケーション」を技術・表現の両面からシミュレートし、実装能力とプロダクト・マネジメント能力を飛躍的に向上させることが、この挑戦の本質的な動機でした。

### 2. アプリケーションの概要と「煽りLGTM」の概念

「煽りLGTMジェネレーター」は、エンジニアの日常的な承認作業に、あえて「本音」という名の楔を打ち込む、創造的な画像生成ツールです。ユーザーは、用意された背景テンプレート（炎上する部屋、宇宙、爆益グラフなど）を選択し、そこに「（※コード一切読んでないけど）」「（※動けばヨシ！）」といった、心の中に秘められた「煽り文句」を加えることで、強烈なインパクトを持つLGTM画像を生成できます。

#### 2.1. 承認の裏側にある「胃壁を削る」本音の可視化
従来のLGTM画像は、単なる肯定のサインでした。しかし、本アプリではその肯定の裏側に潜む「諦め」「懸念」「皮肉」を言語化します。
例えば、最も人気のあるプリセット「（※本番でバグらないことを祈ります）」は、一見すると謙虚ですが、その実、エンジニアがコードの品質に対して抱く拭い難い不安を端的に表現しています。

この「表面的な肯定（LGTM）」と「直感的な拒絶（本音）」のギャップを埋めることこそが、本ゲーム（あるいはツール）がプレイヤーに伝えたかったメッセージの核心です。安易な「承知いたしました」の代わりに、あえて毒のある画像を送りつける。これは、単なる煽りではなく、エンジニアリングにおける「誠実な疑念」の表明でもあるのです。

#### 2.2. アイデンティティとしてのテンプレート選定
提供されるテンプレートは、エンジニアの心理状態やプロジェクトの状況を象徴的に表しています。
• **This is Fine (炎上)**: 深刻な納期遅延やバグに直面しながらも、平静を装わなければならない矛盾。
• **Stonks (爆益)**: 無理な実装が一時的に成功した際の、根拠のない万能感。
• **万物悟り (宇宙)**: あまりに理解不能な設計に直面し、思考が銀河の彼方へ飛躍した状態。
これらの視覚的記号は、エンジニアなら思わず苦笑してしまうような「毒」を含んでいます。算出された結果は即座にダウンロード可能で、GitHubのPRコメントやX（旧Twitter）へ投稿できるよう設計されており、他者との共有を通じて「自分は今、どのような心境で開発に向き合っているのか」を可視化。リプレイ性を高め、コミュニティ内での「共通言語」としての深みを持たせました。

### 3. 使用した技術スタックとその選定理由

本プロジェクトの開発にあたっては、2026年現在のフロントエンド開発において最も洗練され、かつ高いパフォーマンスを発揮できる最新の技術スタックを選択しました。

#### 3.1. Next.js 16 (App Router)
基盤には最新のNext.js 16を採用しました。今回のアプリは単一のページで完結するシンプルな構成ですが、あえてNext.jsを選んだ理由は、今後の拡張性と「開発体験（DX）」の向上にあります。App Routerによる直感的なディレクトリ構造と、サーバーサイドでのOG画像生成（Metadata API / @vercel/og）の親和性は、SNSでの拡散やGitHubへの貼り付けを前提としたプロダクトにおいて不可欠な要素でした。また、TypeScriptとの強力な統合により、テンプレートデータからパラメータまでを型安全に管理し、開発効率を最大化しました。

#### 3.2. @vercel/og によるエッジ画像生成
本アプリの「心臓部」といえるのが、 `@vercel/og` を用いた動的な画像生成ロジックです。従来のサーバーサイド生成では負荷が課題となりますが、Satoriエンジンを活用したエッジ実行により、ユーザーがテキストを入力した瞬間に「本物」の画像を生成・プレビューすることを可能にしました。
特に、背景がグラデーションのカラーモードと、画像ベースのミームモードをシームレスに切り替える実装は、コードの柔軟性と実行速度のバランスを極限まで追求した結果です。

#### 3.3. Tailwind CSS v4
スタイリングにはTailwind CSSの最新バージョン（v4）を導入しました。このアプリでは、ダークモードを基調とした「重厚感のあるテックUI」を目指しました。v4の新機能であるユーティリティクラス（`bg-linear-to-r` 等）を駆使し、ガラスモーフィズムを多用したコントロールパネルや、テンプレート選択時の滑らかなアニメーション（hover時のスケール変化）を、極めて低オーバーヘッドで実装しました。CSS-in-JSに頼らない低遅延なスタイル適用は、リアルタイムプレビューの快適性に大きく寄与しています。

### 4. フロントエンドの実装詳細：高速プレビューエンジンの構築

「煽りLGTMジェネレーター」の核心は、 `src/app/page.tsx` に集約された高度なリアクティブ・ロジックにあります。

#### 4.1. デバウンス処理とUXの最適化
ユーザーがテキストを入力するたびにAPIリクエストを飛ばすと、ネットワーク負荷が増大し、ユーザー体験を損ないます。そこで、 `useEffect` と `setTimeout` を組み合わせた200msのデバウンス処理を実装しました。
この「溜め」があることで、入力の合間を縫って効率的にプレビューを更新しつつ、タイピングの軽快さを損なわない設計となっています。これは、単なるコードの実装ではなく、ユーザーが「画像を作っている」という感覚を維持するための、UXエンジニアリングにおける重要な判断でした。

#### 4.2. クロスオリジンと画像ダウンロードの制御
生成されたプレビュー画像をブラウザ上で「画像としてダウンロード」させるためには、 `crossOrigin="anonymous"` の適切なハンドリングと、 `canvas` を介さない `fetch` ＋ `Blob` 生成によるダウンロードロジックが必要です。
特に本プロジェクトでは、Vercel Edge Functionから返されるPNG画像を直接ダウンロード対象にすることで、クライアントサイドでの描画負荷を最小限に抑えつつ、最高画質の成果物を提供することを実現しました。この「画像のポータビリティ」こそが、ツールの実用性を支える基盤となっています。

### 5. コンテンツ設計：煽りの言語化と言語モデル

本アプリケーションの「教育的価値」と「エンターテインメント性」を両立させているのが、 `PRESETS` 定数に定義された「エンジニアの本音」の言語化です。

#### 5.1. 煽り文句の4分類と社会心理学的アプローチ
単に「嫌な言葉」を並めるのではなく、実務で発生するコミュニケーションの「裏側」をいくつかのカテゴリに分類しました。

1. **技術的負債への諦諦**: 「（※動けばヨシ！）」に代表される、品質よりも納期や動作を優先せざるを得ない現場の妥協点。これは、開発者としての良心と現実のトレードオフを象徴しています。
2. **責任回避のユーモア**: 「（※本番でバグらないことを祈ります）」という、祈祷としてのエンジニアリング。科学的であるべきプログラミングが、複雑性ゆえに神秘的な運任せになる瞬間の滑稽さを突いています。
3. **皮肉な全能感**: 「（※これが俺たちのフルスタックだ）」といった、泥臭い実装をあえて高尚な言葉で飾る自虐。これは、過酷な環境を生き抜くための防衛機制としてのユーモアです。
4. **徹底した沈黙（拒絶）**: 「（※......。）」という、言葉を失うほどのコード。あえて言葉にしないことで、そのコードの深刻さを伝える、究極の「拒絶の審美眼」を表現しています。

#### 5.2. 「プリセット」という思考のバイパス
ユーザーが自由に入力できる機能に加え、あえて強力なプリセットを用意したのは、エンジニアが「言いたくても言えなかったこと」を一瞬で見つけ出し、ボタン一つで代弁させるためです。「自らの言葉で拒絶するのは難しいが、テンプレートに従う形なら表現できる」。この心理的ハードルの低下が、ツールの利用率と中毒性を高める鍵となりました。

### 6. SNS連携とバイラル設計：エンジニアの「承認欲求」を刺激する

本プロジェクトを個人の趣味開発で終わらせず、多くのエンジニアに届け、議論のきっかけにするためには、強力な「バイラル・ループ」の構築が不可欠でした。

#### 6.1. 共有される「作品」としてのLGTM
画像が生成された瞬間、それは単なるファイルではなく、開発者としての「主張」を含んだ作品になります。GitHubのプルリクエストにこの画像が貼られた際、他のレビュアーや作成者がどのような反応を示すか。この「リアクションの連鎖」こそをプロダクトとして設計しました。
「あの有名な煽りLGTMで承認された」という事実が、チーム内の空気を和らげたり、あるいは逆に「もっと良いコードを書かなければ」という健全なプレッシャーを与えたりする。ツールの外部で起きる人間関係のダイナミズムを、画像一枚でコントロールすること。それがデザインの本質的な狙いでした。

#### 6.2. OGPによるタイムラインの支配
GitHubやXでURLがシェアされた際のプレビュー（OGP）も、 `@vercel/og` で動的に生成されます。
シェアされたリンクを見るだけで、その人がどんな「煽り」でコードを評価したのかが一目でわかる。この「中身が見えるシェア」の実装により、クリック率と認知度が飛躍的に向上しました。タイムライン上に次々と流れてくる多種多様な「煽り」は、それ自体がコンテンツとなり、新たなユーザーを惹きつける磁石となりました。

### 7. 直面した課題と技術的な反省点：理想と現実のギャップ

開発プロセスは常に順風満帆ではありませんでした。特に最新の技術スタックを採用したからこそ直面した、固有の課題がいくつか存在します。

#### 7.1. 画像読み込みの遅延とスケルトンUIの不在
初期の実装では、OGP APIからの画像返却を待つ間、プレビューエリアが空白になってしまう現象が発生しました。これは「高速な生成」を掲げるツールにとって致命的な減点要素です。
この反省から、ローディングステート（ `isGenerating` ）を導入し、Lucideアイコンの `RefreshCw` によるアニメーション表示を実装しました。また、Next.jsの `Image` コンポーネントの挙動を参考に、画像が完全に取得されるまで前の画像を維持する、あるいは適切なプレースホルダーを表示するロジックへと磨き上げました。

#### 7.2. テンプレートの多様性とデータのスケーラビリティ
当初、テンプレート画像は `src` 内にハードコードしていましたが、種類が増えるにつれてコードの見通しが悪化しました。
そこで、 `TEMPLATES` 定数を完全に分離し、各テンプレートが持つメタデータ（id, name, bg, mode, thumb）を型定義（Interface）に基づいて厳格に管理する構造へとリファクタリングしました。これにより、将来的にユーザーがカスタムテンプレートをアップロードしたり、DBからテンプレートを動的に取得したりするための拡張性を確保しました。

### 8. 今後の展望と追加機能のアイデア：進化する煽り

今回の開発で基盤となる「画像生成エンジン」は完成しましたが、このプロダクトはまだ進化の途上にあります。

#### 8.1. AIを用いた「コンテキストに応じた煽り生成」
今後はLLMをAPI経由で連携させ、ユーザーが書き込んだコメントや、あるいはGitHub APIと連携してプルリクエストの「差分（diff）」を解析し、そのコードの脆弱性や汚さに合わせた「最適な煽り」を自動で提案する機能を構想しています。AIが冷徹なロジックでコードを切り裂き、最もダメージの大きい煽り文句を生成する。それは、人間による主観的な批判を超えた、新たな「技術的防衛」の形になるはずです。

#### 8.2. グローバル・ランキングと「最も煽られたコード」
Vercel KVを活用し、どの煽り文句が最も多くシェアされたか、どのテンプレートが「炎上」に多用されているかをランキング化する機能を予定しています。これにより、「現代のエンジニアが最も苦しんでいる不本意な承認（LGTM）」の傾向を統計的に明らかにし、業界全体の技術的意識の向上に向けた「社会学的データ」としての価値を持たせたいと考えています。

### 9. 結論・全体のまとめ

この「煽りLGTMジェネレーター」プロジェクトの完遂を通じて、私はエンジニアとして重要なパラダイムシフトを経験しました。
プログラミングとは単にコンピュータに命令を送る行為ではなく、情報の非対称性を解消し、技術というメディアを通じて人間の本音を適切に翻訳・交換する行為であるという気づきです。Next.js 16やTailwind v4といったモダンな技術は、その目的を果たすための強力な「武器」であり、それらをいかに効率的に配置するかが、エンジニアの真の職能であることを再確認しました。

「技術を磨き、安易な肯定を拒絶し、本音という名のスパイスでプロダクトの品質を守る」。本プロジェクトで培ったこの批評的精神を糧に、今後もより大規模で、価値あるシステム開発に挑戦し続けていきたいと思います。

クリーンなコードは、勇気ある本音の言語化から始まる。
「Looks Good To Me」という呪文で思考を止めるのではなく、その裏にある違和感に正直になること。それが、このプロジェクトを通じて私が得た最大の収穫であり、プロダクトを通じて世のエンジニアに伝えたかったメッセージです。

本プロジェクトが、どこかで理不尽な納期や不本意なコードと戦い続ける全てのエンジニアたちの、ささやかなストレス解消と、技術への「誇り」を守るための盾となることを願っています。
これからの開発の道は決して平坦ではありませんが、この「拒絶と肯定のバランス」を追求し続けることで、私たちはより透明性が高く、より創造的なエンジニアリングの未来を築くことができると確信しています。
